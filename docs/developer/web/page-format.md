# 页面与组件规范

适用于 `apps/web/app/pages/` 下的页面和 `apps/web/app/components/` 下的组件。单文件组件依次放置 `<script setup lang="ts">`、`<template>`、`<style scoped>`。本节先约定基本顺序与职责，具体场景后续补充。

## 页面

页面负责组织数据请求、路由与全局状态，并将数据传给组件，参考 `pages/index.vue`。script 按下表排列，每个分区使用一行中文注释，分区之间空一行；没有内容的分区直接省略。

| 顺序 | 分区注释 | 内容 |
| --- | --- | --- |
| 1 | `// 导入` | 类型、组件、组合式函数与工具导入；保留 Nuxt 自动导入习惯，不重复显式导入 |
| 2 | `// 页面配置与类型` | `definePageMeta`、页面专用类型，以及需要时的 `defineProps`、`defineEmits` 等声明 |
| 3 | `// 系统变量读取` | 路由、运行配置、全局状态、系统时间等，例如 `useRoute()`、`useRuntimeConfig()`、`useSystemTime()`、`useAppPeferences()` |
| 4 | `// API 读取` | `useApi` 客户端及读写配置，按上游到下游的顺序排列；读写同一资源的配置放在一起 |
| 5 | `// 页面变量：普通变量` | 页面常量、非响应式临时状态、定时器句柄等，优先使用 `const`，需要重新赋值时使用 `let` |
| 6 | `// 页面变量：响应式数据` | `ref`、`reactive`、模板引用，以及 API 响应与共享缓存的解构、别名 |
| 7 | `// 计算属性` | `computed` 派生值，先声明基础计算，再声明依赖它的计算 |
| 8 | `// 方法` | 业务方法、事件处理、请求写入与刷新操作，先辅助方法，再使用它们的方法 |
| 9 | `// 监听` | `watch`、`watchEffect` 等响应式副作用 |
| 10 | `// 生命周期` | 挂载、更新、卸载等钩子；申请资源和清理资源的逻辑应对应 |
| 11 | `// 对外暴露` | 页面确有需要时使用 `defineExpose` 等声明 |

## 组件

组件按功能归组，同一功能的变量、计算属性、辅助方法和 watch 放在一起，参考 `ScheduleTable.vue` 的职责划分。props 补简短注释说明用途，必要时注明单位、默认值或空值含义；其余部分保留必要的已有注释，不要求添加分区标题。

| 顺序 | 内容 | 放置方式 |
| --- | --- | --- |
| 1 | 组件与依赖、专用类型 | 使用的子组件放在导入区域前面，必要的 interface、type 放在开头；优先自动推断和 `ApiData`，不重复定义接口数据类型 |
| 2 | 参数与事件 | `defineOptions`、`defineProps`、`defineEmits`、`defineModel` 等声明；props 的说明紧邻参数 |
| 3 | 数据处理 | 对传入数据的筛选、排序、转换、校验，以及相应的状态、辅助方法和 watch；组件负责的 API 客户端也按业务归入这里 |
| 4 | 界面参数 | 尺寸、坐标、布局、动画、模板引用、弹窗状态等，以及对应的计算、辅助方法和 watch |
| 5 | 生命周期 | DOM 初始化、订阅、缓存激活和资源清理等钩子 |
| 6 | 点击与交互操作 | 点击、拖动、键盘、表单提交等入口，以及保存、删除后的事件处理 |
| 7 | 对外暴露 | 确有需要时在最后使用 `defineExpose` |

同一方法同时承担数据和界面职责时，按主要用途就近放置。仅整理顺序时保留方法本身，不为了分区拆分函数、增加状态或改变调用方式。

`DatePicker` 传入 `initial-date` 时打开指定日期所在的普通自然周，并定位到该日。任务编辑器传入原截止日期时间。省略参数时从本周打开，把已过的星期换成下周同一天并标注「下周」。横向拖动或使用左右方向键切换周，传入阶段时显示阶段内周次。星期圆球复用 `WeekPicker` 单选，通过 `@select` 接收点选的 `YYYY-MM-DD` 日期，或通过 `v-model` 绑定本地日期时间。`default-time` 用于选择新日期，默认 `24:00`。

任务编辑器的 `TimePicker` 刻度从卡片左边缘起笔，每五分钟一格，整点更长。左侧的蓝色三角与居中的所选时间对齐。详情收起时整张编辑卡片可竖拖，展开后仅时间行响应竖拖。慢拖时保留到分钟，甩动产生的惯性动画停在最近的五分钟刻度。其他字段和删除入口在「详情」。保存 `24:00` 时使用所选日期在偏好时区的最后一毫秒，使任务仍归入当天的日程。

## 通用数据与依赖约定

- API 客户端使用 `reactive(useApi(...))` 保持数据和状态的响应式关联，不额外使用 `useAsyncData` 或 `refreshNuxtData` 管理同一份数据。API 区负责声明客户端，页面变量区提取页面使用的数据与状态，例如 `client.data`、`client.read.loading`。设置 `watch: true` 后，首次读取和 key 变化后的读取由 `useApi` 自动触发，页面无须重复写 watch；未启用时通过方法、监听手动读取。页面重读与保存后的更新直接调用 `client.read()`，检查服务器 version 后决定复用缓存或重新获取数据，不使用 `read.refresh()` 强制刷新。
- API 的动态 key 和读取回调优先从已声明的系统变量或上游请求状态取值，避免依赖后方尚未初始化的页面变量或 `computed`。例如首页通过 `useAppPeferences()` 取得全局偏好，阶段请求从 `preferences.value?.defaultPhaseId` 取 ID。
- 完整偏好由 `useAppPeferences()` 共享，只在 `app.vue` 的 `onMounted` 中调用 `initialize()` 读取。页面直接修改全局偏好字段，初始化后的深度监听自动调用 `useApi.write()` 保存；初始化赋值不会触发写入，保存响应不回填覆盖前端状态。组件无需自行请求、刷新或提交偏好；阶段详情与其加载、刷新逻辑留在页面。
- API 确实依赖页面输入状态时，将必要的状态声明提前到对应请求之前，并用简短注释说明依赖；初始化正确性优先于机械排列，不要为了顺序添加重复状态或无意义的包装函数。
- 业务数据读取保留在页面，通过独立 props 按 `phase`、`events`、`tasks`、`tips` 等实体传递组件所需的数据，操作回调单独传入，不将整套客户端或 `editor` 上下文打包传递，也不从页面导出组件的数据类型；`edit` 目录的阶段、课程、排课和任务写入由对应编辑组件内部使用 `useApi`，保存或删除后发出事件，由页面调用 `read()` 更新受影响的数据；图片上传、预览、背景与轮播由图片组件内部使用 `useApi`。接口数据优先由 `ApiData`、`Parameters` 和自动推断取得类型；必要的页面专用 interface 放在页面配置与类型分区。
- 样式由 `useAppStyle()` 全局共享并在 `app.vue` 初始化，各处修改同一个草稿，实时预览。点击保存才调用 `write()`；撤销直接恢复已保存快照，不发送写入请求。切换预设保留各自尚未保存的草稿。
- `computed` 用于派生数据；请求写入、DOM 操作等副作用放入方法、监听或生命周期。
- 监听可能立即执行，放在它所依赖的变量和方法之后。生命周期钩子在 setup 阶段同步注册，不要放进定时器或异步回调中注册。

## 生命周期内部顺序

按挂载、更新、卸载的阶段排列，每个阶段先 before、后完成钩子：

```ts
// 生命周期
onBeforeMount(() => {
  // 挂载前准备
})
onMounted(() => {
  // 挂载后初始化 DOM 或订阅
})

onBeforeUpdate(() => {
  // 更新前处理
})
onUpdated(() => {
  // 更新后处理
})

onBeforeUnmount(() => {
  // 卸载前清理
})
onUnmounted(() => {
  // 卸载后处理
})
```

以上仅展示排列方式，页面和组件只保留需要的钩子。使用 KeepAlive 时，将 `onActivated`、`onDeactivated` 放在挂载阶段之后；错误捕获等其他钩子按用途就近归组。

## 格式与修改范围

使用两个空格缩进、单引号、不加分号，保持现有 ESLint 风格。分区注释用于说明职责，细节注释仅在依赖、边界条件或业务规则需要解释时添加。纯格式整理应保留请求选项、响应式行为与模板交互，不顺带加入功能或占位声明。

基础 CSS 尽量按模板中的 DOM 顺序排列，`@media`、`@container` 等响应式规则集中放在后面，内部选择器顺序与基础样式尽量一致。需要整理 CSS 时展开规则，每个属性单独一行，并保留原有的层叠关系与样式值。

声明顺序以依赖和初始化正确性为先。调整已有代码时，保留 watch 与生命周期的注册先后、立即执行行为和清理逻辑；没有内容的部分直接省略。

响应式与生命周期行为参考 [Vue reactive](https://cn.vuejs.org/api/reactivity-core.html#reactive) 与 [Vue 生命周期钩子](https://cn.vuejs.org/api/composition-api-lifecycle.html)；上述分区顺序为本项目约定。
